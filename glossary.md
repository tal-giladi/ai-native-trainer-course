## A

- **A/A test** — Running the same configuration twice to check that the evaluation setup itself produces no difference ([lesson 7.5](lessons/module-07/lesson-05.md))
- **Ablation** — Removing or restoring one element at a time and rerunning the affected tasks to find which element a result depends on ([lesson 4.5](lessons/module-04/lesson-05.md))
- **Acceptance criterion** — A condition for accepting a deliverable that a third person could check, unlike "to the client's satisfaction" ([lesson 20.4](lessons/module-20/lesson-04.md))
- **acted-on rate** — The share of posted agent comments that lead to a code change; the production signal for CI-review precision ([lesson 11.2](lessons/module-11/lesson-02.md))
- **adjudication** — A human re-examining agent findings that matched no known defect and adding confirmed ones to the ground truth ([lesson 11.2](lessons/module-11/lesson-02.md))
- **Adoption funnel** — The stages from seats assigned to activated, weekly active and engaged use; habitual users are the product of the stage conversion rates ([lesson 19.1](lessons/module-19/lesson-01.md))
- **Adoption regression** — Usage falling back after a rollout, as a step (something changed), a decay (support and habit fading), a measurement gap or a cohort that never started ([lesson 19.4](lessons/module-19/lesson-04.md))
- **Advisory vs deterministic control** — Advisory controls (rules, skills) are context the model weighs; deterministic controls (hooks, permissions, tests, CI gates) run the same way every time ([lesson 3.2](lessons/module-03/lesson-02.md))
- **agent loop** — The harness cycle of calling the model, executing requested tools, returning results and repeating until the model stops or a limit is hit ([lesson 2.4](lessons/module-02/lesson-04.md))
- **Agent trace** — One record per task with one span per agent call (role, round, timing, cost, tokens, verdict, files) and a stop reason, used to find where a failure originated ([lesson 10.3](lessons/module-10/lesson-03.md))
- **AGENTS.md** — Open Markdown convention for repository instructions read by many coding agents; the nearest file in the directory tree takes precedence ([lesson 3.2](lessons/module-03/lesson-02.md))
- **Agents Rule of Two** — Meta's design rule that an agent session should satisfy at most two of {untrusted input, sensitive access, external communication}, assuming injection will sometimes succeed ([lesson 9.1](lessons/module-09/lesson-01.md))
- **AI layer** — The versioned set of files in a repository that shape coding-agent behavior: rules files, skills, sub-agent definitions, MCP configuration, hooks, CI agent workflows, eval tests and their governance ([lesson 3.1](lessons/module-03/lesson-01.md))
- **AI-layer changelog** — A log with one entry per AI-layer change recording what changed, the triggering incident, the evidence and how it was verified ([lesson 3.1](lessons/module-03/lesson-01.md))
- **AI literacy** — The skills, knowledge and understanding to use AI systems in an informed way; EU AI Act Article 4 requires providers and deployers to take measures to support it for their staff ([lesson 19.3](lessons/module-19/lesson-03.md))
- **Always-loaded context** — Instructions loaded into every session at start, such as a root CLAUDE.md, its imports and rules without a path scope ([lesson 4.2](lessons/module-04/lesson-02.md))
- **Answer leakage** — Task prompts or expected answers copied into the AI layer, so the eval measures reading an answer key rather than competence ([lesson 7.2](lessons/module-07/lesson-02.md))
- **append-only (WORM) audit log** — An audit trail stored so that records can be added but not modified or deleted, including by the people being audited ([lesson 12.3](lessons/module-12/lesson-03.md))
- **approval gate** — A human-in-the-loop checkpoint on a high-impact action, bounding the blast radius of a successful injection to a prompt that can be refused ([lesson 9.4](lessons/module-09/lesson-04.md))
- **architecture decision record (ADR)** — A short, numbered, immutable record of one architecturally significant decision: context, options considered, decision, consequences and how compliance is confirmed ([lesson 12.5](lessons/module-12/lesson-05.md))
- **attention** — The mechanism by which each token weighs earlier tokens through a softmax over query-key scores; the weights compete, so irrelevant context can dilute relevant context ([lesson 2.1](lessons/module-02/lesson-01.md))
- **Attribution audit** — A check of every borrowed term, shape, diagram and example against public frameworks, with a decision for each: attribute, replace or justify ([lesson 14.4](lessons/module-14/lesson-04.md))
- **Audit hook** — A hook that records each tool call (tool, target, outcome, input hash) with secrets redacted; local logs are evidence for the developer, not a tamper-proof audit trail ([lesson 8.4](lessons/module-08/lesson-04.md))

## B

- **Background IP** — The method, templates, tools and materials you owned before an engagement; a SOW keeps them yours and licenses what is embedded in the client's deliverables ([lesson 20.5](lessons/module-20/lesson-05.md))
- **Backward design** — Planning a session from desired results to assessment evidence to activities, in that order (Wiggins and McTighe) ([lesson 16.2](lessons/module-16/lesson-02.md))
- **bare mode** — Claude Code's `--bare` flag: a headless run loads no hooks, skills, MCP servers or CLAUDE.md implicitly, so the job passes the layer and settings it means to use ([lesson 11.1](lessons/module-11/lesson-01.md))
- **base-rate ceiling** — The upper bound on a reviewer's precision set by comment volume: precision ≤ known defects / comments, however good the model ([lesson 11.2](lessons/module-11/lesson-02.md))
- **baseline** — The before-state of every outcome an engagement will measure, captured from history before the build starts, with definitions, a spread and a quality guardrail ([lesson 21.2](lessons/module-21/lesson-02.md))
- **Baseline (eval)** — A committed, pinned, full-suite result that candidate changes are gated against; regenerated when the agent version or model changes ([lesson 7.6](lessons/module-07/lesson-06.md))
- **Before/after tags** — Two tags on the demo repository, one with an empty AI layer and one with the layer, between which only AI-layer paths change and the demo ticket stays open ([lesson 15.2](lessons/module-15/lesson-02.md))
- **Benchmark contamination** — Benchmark tasks or solutions present in a model's training data, so the score partly measures memory ([lesson 7.2](lessons/module-07/lesson-02.md))
- **Blast radius** — Everything that calls, reads or depends on the code a change will modify: callers, tests, schema, configuration ([lesson 5.1](lessons/module-05/lesson-01.md))
- **blast radius (of a credential)** — The share of teams or systems a leaked credential can reach, k/T for a credential shared by k of T teams ([lesson 12.3](lessons/module-12/lesson-03.md))
- **Blocker** — A stakeholder or constraint that can stop the work (CISO, DBA lead, legal); designed for early, not solved ([lesson 1.2](lessons/module-01/lesson-02.md))
- **Blocking (stratified randomization)** — Randomizing separately within groups fixed before assignment (for example developer × size) so the arms are balanced on them and the analysis can remove their variation ([lesson 13.3](lessons/module-13/lesson-03.md))
- **Bootstrap confidence interval** — An interval from the spread of an estimate recomputed on many resamples of the data drawn with replacement ([lesson 13.5](lessons/module-13/lesson-05.md))
- **break-even acceptance** — For a recurring automation, the acceptance rate a* = r/s (review minutes per proposal over minutes saved per accepted proposal) below which it costs more time than it saves ([lesson 11.3](lessons/module-11/lesson-03.md))
- **Brownfield audit** — A five-pass review of an existing codebase (topology, build/test, SQL conventions, legacy patterns, tribal knowledge) to find what an agent would get wrong, with evidence ([lesson 3.3](lessons/module-03/lesson-03.md))
- **Brownfield demo** — A purpose-built, confidentiality-safe legacy repository with real history, hidden conventions, a company around it and a tagged before/after, used for every public demo instead of employer code ([lesson 15.1](lessons/module-15/lesson-01.md))
- **budget breaker** — A scheduled check that sums the day's agent spend and disables the offending workflows when a ceiling or a retried cap failure is found ([lesson 11.4](lessons/module-11/lesson-04.md))
- **Buyer / user / champion** — Who signs and owns budget; who lives the pain daily; who wants it to succeed and carries evidence into rooms you are not in ([lesson 1.2](lessons/module-01/lesson-02.md))
- **byte-pair encoding (BPE)** — Tokenization method that builds a vocabulary by repeatedly merging the most frequent adjacent byte pairs; frequent strings become one token, rare ones fragment ([lesson 2.1](lessons/module-02/lesson-01.md))

## C

- **canary** — A harmless marker value (e.g. CANARY-7f3a) planted so a test can observe whether an attack reached a sink, without any real secret or payload ([lesson 9.2](lessons/module-09/lesson-02.md))
- **Capability eval / regression eval** — A suite that measures what an agent cannot yet do reliably (low pass rate) versus one that guards what it already does (pass rate near 100%) ([lesson 7.1](lessons/module-07/lesson-01.md))
- **Capacity cap** — The stated number of days a month you sell, kept in practice and published in the application form, with a rule for what happens when it is full ([lesson 22.4](lessons/module-22/lesson-04.md))
- **Capped retainer** — A monthly retainer with a day cap, expiry of unused days, a notice period and a scope, priced per capped day ([lesson 22.4](lessons/module-22/lesson-04.md))
- **case study** — A one-page, anonymized, client-approved account of one engagement whose every number and status comes from the engagement record, with limitations as a section ([lesson 21.5](lessons/module-21/lesson-05.md))
- **Catch-up tag** — A git tag holding the finished state of a hands-on step, so a learner who falls behind can join the next step with everyone else ([lesson 17.2](lessons/module-17/lesson-02.md))
- **Ceiling effect** — Items or tests most learners already pass before teaching, which therefore cannot show learning ([lesson 16.5](lessons/module-16/lesson-05.md))
- **Certificate of completion** — A document stating that a learner attended, did the exercises and took the assessment, without claiming job competence; contrasted with a credential, which needs validity evidence and a defended cut score ([lesson 22.3](lessons/module-22/lesson-03.md))
- **chain of command** — OpenAI Model Spec term for the ordered levels of instruction authority; tool outputs and file contents carry no authority unless delegated ([lesson 2.3](lessons/module-02/lesson-03.md))
- **Champion** — A peer inside one team with sanctioned hours to make the agent useful for that team: first responder, local examples, team rules owner, feedback conduit, practice host ([lesson 19.2](lessons/module-19/lesson-02.md))
- **change class** — A category of AI-layer change (wording, behavior, capability and trust, platform) that sets the review and evidence it needs ([lesson 11.5](lessons/module-11/lesson-05.md))
- **Change management** — The planned work of moving people from current to new ways of working: stakeholders, champions, enablement, measurement and the mechanisms that keep the change after its sponsors move on ([lesson 19.1](lessons/module-19/lesson-01.md))
- **Change request** — A written request to change scope, schedule or deliverables that states its effect on fee and schedule and is approved before work on it starts ([lesson 20.4](lessons/module-20/lesson-04.md))
- **Changelog** — A human-readable, newest-first record of notable changes per release (Added, Changed, Deprecated, Removed, Fixed, Security), as in Keep a Changelog ([lesson 22.3](lessons/module-22/lesson-03.md))
- **chargeback / attribution coverage** — Allocating model spend to the teams that caused it; coverage is the share of spend on keys owned by a team ([lesson 12.2](lessons/module-12/lesson-02.md))
- **Claims ladder** — Levels of claim from observation, effect in this study, effect for this team, effect elsewhere, to money, each requiring more evidence than the last ([lesson 13.6](lessons/module-13/lesson-06.md))
- **client-authored share** — The fraction of AI-layer changes in a period whose author is a client employee; in the last third of a build it should be at least 70% ([lesson 21.3](lessons/module-21/lesson-03.md))
- **Cliff's delta** — The probability that a random value from one group exceeds one from the other, minus the reverse; an assumption-free effect size ([lesson 13.5](lessons/module-13/lesson-05.md))
- **CODEOWNERS** — GitHub file mapping path patterns to owners who are requested for review; the last matching pattern wins, and review is binding only with branch protection or rulesets ([lesson 3.1](lessons/module-03/lesson-01.md))
- **Cognitive load** — Demand on limited working memory; intrinsic load comes from the material, extraneous load from the design and can be removed ([lesson 16.2](lessons/module-16/lesson-02.md))
- **Cold-use test** — A colleague uses a skill on a ticket of their choosing without any help; where they get stuck shows the skill's unclear inputs and outputs ([lesson 6.4](lessons/module-06/lesson-04.md))
- **Commitment (discovery)** — Something a participant spends now — an introduction, data, a second session — as opposed to a compliment or a promise ([lesson 1.4](lessons/module-01/lesson-04.md))
- **Community rules** — The terms that make a paid community a bounded product: response time, office hours, exclusions, moderation and what happens if it closes ([lesson 22.2](lessons/module-22/lesson-02.md))
- **Compact instructions** — Guidance in the root CLAUDE.md, or a focus passed to /compact, that tells the summarizer what must survive ([lesson 4.4](lessons/module-04/lesson-04.md))
- **Compaction** — Replacing older conversation history with a model-written summary so a session can continue; lossy by design ([lesson 4.4](lessons/module-04/lesson-04.md))
- **Company scaffold** — The fictional organization around a demo repository: handbook, team, glossary, PRDs, tickets in a tracker and at least one stale page ([lesson 15.2](lessons/module-15/lesson-02.md))
- **Compute-matched baseline** — A single agent allowed the same kinds of work as a multi-agent arm (plan, test, re-check), so a comparison isolates the effect of having several agents ([lesson 10.4](lessons/module-10/lesson-04.md))
- **Concept card** — The record of one concept: status, date named, plain-words definition, claim, boundary, counter-evidence and dated evidence trail ([lesson 14.2](lessons/module-14/lesson-02.md))
- **Concept (in a method)** — A named, bounded, falsifiable claim about how agent work fails or succeeds, traced to dated incidents or experiments ([lesson 14.2](lessons/module-14/lesson-02.md))
- **Confounder** — A variable that influences both who gets the treatment and the outcome, such as ticket size when developers choose when to use an agent ([lesson 13.3](lessons/module-13/lesson-03.md))
- **Constructive alignment** — The verb in the objective is the verb the learner performs in the activity and in the assessment (Biggs) ([lesson 16.2](lessons/module-16/lesson-02.md))
- **Consultant** — Sells an outcome: an engineering metric that moves; judged by a before/after number with an interval ([lesson 1.1](lessons/module-01/lesson-01.md))
- **Contamination** — Units in the control arm receiving the treatment (or treatment units skipping it), which dilutes the measured effect ([lesson 13.4](lessons/module-13/lesson-04.md))
- **Content funnel** — A model of public teaching in three stages: discover (a stranger meets one idea), trust (they can apply it and come back) and act (a piece asks for something); asks are kept to at most one piece in five ([lesson 18.1](lessons/module-18/lesson-01.md))
- **Context audit** — Sorting every piece of a context layer into must always know, retrieve when needed, never load or generate dynamically, then proving the change on a fixed task set ([lesson 4.5](lessons/module-04/lesson-05.md))
- **Context budget** — What is left of the window for the task's working material: B = W − S − R − T − H − O (window minus system prompt, rules, tools, history and output reserve) ([lesson 4.1](lessons/module-04/lesson-01.md))
- **Context engineering** — Curating the smallest set of tokens — system instructions, tools, rules, retrieved data and history — that lets an agent do the task, on every turn ([lesson 4.1](lessons/module-04/lesson-01.md))
- **Context isolation** — Keeping a delegated task's reading and tool output out of the caller's context, so only its summary returns ([lesson 6.3](lessons/module-06/lesson-03.md))
- **Context pollution** — Residue in a session's history — failed attempts, abandoned plans, large tool outputs — that degrades later turns and disappears with a reset ([lesson 4.3](lessons/module-04/lesson-03.md))
- **Context rot** — Degradation of a model's recall and accuracy as the number of tokens in its context grows ([lesson 4.1](lessons/module-04/lesson-01.md))
- **context window** — The maximum number of tokens, input plus output, a model can attend over in one request ([lesson 2.1](lessons/module-02/lesson-01.md))
- **Contradictory context** — Two loaded instructions that disagree, within a file, across files, across directory levels or across tools; typically produces answers that flip between runs ([lesson 4.3](lessons/module-04/lesson-03.md))
- **Control arm** — A concurrent comparison group doing the same kind of work at the same time without the treatment ([lesson 13.3](lessons/module-13/lesson-03.md))
- **Convention test** — A unit test that fails the build when code breaks a house convention, guarding both the code and the rules that describe it ([lesson 3.4](lessons/module-03/lesson-04.md))
- **Core skills** — The five procedure skills that cover the course's loop: prime, spec, plan-feature, validate and pr-review ([lesson 6.2](lessons/module-06/lesson-02.md))
- **Cost floor** — The day rate below which work makes you poorer: target income plus business costs divided by genuinely sellable days ([lesson 20.2](lessons/module-20/lesson-02.md))
- **Cost per passing answer** — Total cost of a set of runs divided by the number of runs that passed; the cost of one useful result ([lesson 4.5](lessons/module-04/lesson-05.md))
- **cost per successful task** — Cost per attempt divided by success probability, plus expected failures times the human cost of handling one failure ([lesson 2.5](lessons/module-02/lesson-05.md))
- **cost per successful task (with fixed cost)** — (marginal cost per attempt + fixed monthly cost / attempts) / pass rate, plus (1/pass rate − 1) × review cost of a failed attempt; the unit for comparing hosting options that survive the hard constraints ([lesson 12.1](lessons/module-12/lesson-01.md))
- **cost per useful outcome** — Total cost of an agent job divided by the number of its outputs that were applied or merged ([lesson 11.4](lessons/module-11/lesson-04.md))
- **Counter-evidence** — An observation that would contradict a concept's claim; every card states what would count ([lesson 14.2](lessons/module-14/lesson-02.md))
- **Creative Commons licence** — One of six public licences (BY, BY-SA, BY-ND, BY-NC, BY-NC-SA, BY-NC-ND) for creative works; CC recommends against them for software ([lesson 22.2](lessons/module-22/lesson-02.md))
- **Critical path** — The longest sequence of dependent stages in a pipeline; it sets wall-clock latency, since parallel stages cost only their slowest branch ([lesson 10.3](lessons/module-10/lesson-03.md))
- **Customer discovery interview** — A non-selling conversation about specific past events to learn whether a pain is real, who feels it and who pays ([lesson 1.4](lessons/module-01/lesson-04.md))
- **Cut order** — The pre-written order in which agenda steps are shortened when a workshop runs late: show steps first, never hands-on, the reflection or the post-test ([lesson 17.1](lessons/module-17/lesson-01.md))
- **Cycle time** — Time from a ticket entering In Progress to its change being merged; the default speed metric for comparisons because its clock starts before the way of working can act ([lesson 13.1](lessons/module-13/lesson-01.md))

## D

- **data inventory** — A list of every copy of prompt data in a system with where it is processed and stored, how long it is kept, who can read it and which terms govern it ([lesson 12.4](lessons/module-12/lesson-04.md))
- **Data minimization** — Collecting only the personal data a stated purpose needs; on an application form, name and work email ([lesson 20.3](lessons/module-20/lesson-03.md))
- **data residency** — The requirement that data is processed and stored only in named geographies; a property of every path (fallback routes, tools, telemetry), not only the primary route ([lesson 12.4](lessons/module-12/lesson-04.md))
- **Decision before trigger** — The layering rule that a fact the agent must act on before it would open a file under the trigger path belongs, or has a pointer, in the always-loaded layer ([lesson 4.2](lessons/module-04/lesson-02.md))
- **Decoy option** — An offer added mainly to make another option look better by comparison (the asymmetric-dominance effect); excluded from an honest ladder ([lesson 20.1](lessons/module-20/lesson-01.md))
- **Delegation contract** — What a delegation must carry: objective, output format, tools and sources, boundaries, and what to do with unknowns ([lesson 6.3](lessons/module-06/lesson-03.md))
- **Deliberate practice** — Practice designed to improve specific aspects of performance, with feedback, as opposed to repetition (Ericsson et al.) ([lesson 17.4](lessons/module-17/lesson-04.md))
- **Demo drill** — A rehearsal in which a randomly chosen failure is induced in a live segment to practise recovery, after chaos engineering ([lesson 15.4](lessons/module-15/lesson-04.md))
- **Demo ticket** — The one ticket run live, chosen from at least ten measured runs for repeatability, a visible before/after gap, duration and recognizability ([lesson 15.1](lessons/module-15/lesson-01.md))
- **Deny list** — A private list of employer, client, product and colleague names scanned against every commit of a public repository; kept outside that repository ([lesson 15.1](lessons/module-15/lesson-01.md))
- **Deterministic step** — A step of a skill with exactly one right answer, done by a script or command rather than by the model ([lesson 6.1](lessons/module-06/lesson-01.md))
- **Difference-in-differences (DiD)** — The treated unit's change over time minus the comparison units' change over the same time; valid when the treated unit would otherwise have moved in parallel ([lesson 13.4](lessons/module-13/lesson-04.md))
- **direct prompt injection** — An attack where the user's own input carries an instruction intended to override the system or developer prompt ([lesson 9.2](lessons/module-09/lesson-02.md))
- **Disclosure line** — A statement in the piece itself of any material connection to what it discusses, such as an employer, a vendor, free access or payment; "none" when there is none ([lesson 18.2](lessons/module-18/lesson-02.md))
- **Discovery call** — A 30-minute call with an applicant that establishes a past incident, a success measure, the decision path, budget, timing and constraints before any offer is fitted to it ([lesson 20.3](lessons/module-20/lesson-03.md))
- **Discrimination index** — For an assessment item, $D = p_U - p_L$, the difference in correct rates between the top and bottom 27% of learners by total score; negative values suggest a miskeyed or misleading item ([lesson 22.3](lessons/module-22/lesson-03.md))
- **DORA metrics** — DORA's five software delivery metrics: change lead time, deployment frequency and failed deployment recovery time (throughput); change fail rate and deployment rework rate (instability) ([lesson 13.1](lessons/module-13/lesson-01.md))
- **Drift decomposition** — Splitting a rehearsal's timing error into the controlled part (talk and live steps) and the estimated part (hands-on steps), because the two can cancel in the total ([lesson 17.4](lessons/module-17/lesson-04.md))

## E

- **Effect size** — A measure of how large a difference is (ratio of geometric means, Hedges g, Cliff's delta), as opposed to how surprising it is ([lesson 13.5](lessons/module-13/lesson-05.md))
- **effective context** — The length of context over which a model still performs a given task reliably; usually much smaller than the advertised window ([lesson 2.1](lessons/module-02/lesson-01.md))
- **Effective day rate** — A fixed fee divided by the days actually worked on it; compared with your cost floor to see whether a delivery paid ([lesson 22.1](lessons/module-22/lesson-01.md))
- **effective false positive** — A review or analysis finding on which developers take no positive action, whether or not it is technically correct; Google keeps checks under 10% ([lesson 11.2](lessons/module-11/lesson-02.md))
- **Effective number of tools** — The reciprocal of the concentration index $H = \sum s_i^2$ of tool shares; 1 for a single tool, $k$ for $k$ equally used tools ([lesson 19.2](lessons/module-19/lesson-02.md))
- **Effort vs flow** — Engineer-hours of work (bounded by team capacity) versus calendar delay (median, p90); never multiplied into each other when sizing a pain ([lesson 1.2](lessons/module-01/lesson-02.md))
- **egress allowlist** — An OS-enforced list of domains a sandboxed command may reach; an empty list means no host is reachable, unlike a command-text deny rule ([lesson 9.5](lessons/module-09/lesson-05.md))
- **embedding** — The vector a token ID is mapped to before the transformer layers process it ([lesson 2.1](lessons/module-02/lesson-01.md))
- **Enablement** — The recurring mechanisms that make a tool usable in practice: role-based training, practice time, office hours, a feedback loop and ownership ([lesson 19.3](lessons/module-19/lesson-03.md))
- **Enablement engineer** — Internal owner of the AI layer and agent platform; judged by sustained, trusted adoption and fewer incidents ([lesson 1.1](lessons/module-01/lesson-01.md))
- **enabling stance** — Helping a team gain a capability temporarily and then moving on, rather than building on its behalf (after Team Topologies' enabling teams) ([lesson 21.3](lessons/module-21/lesson-03.md))
- **enforcement ladder** — The ordering of ways to encode a rule, from least to most reliable: a sentence in the rules, a skill step, a hook or gate, a test in the build ([lesson 11.5](lessons/module-11/lesson-05.md))
- **engagement record** — The private, phase-by-phase record of one client engagement: stakeholders, acceptors, audit, baseline, decisions, PR log, owners, results and follow-ups; the only source a case study may draw on ([lesson 21.1](lessons/module-21/lesson-01.md))
- **escape cause** — The reason a failure was not caught before it reached review or production, recorded alongside its primary cause ([lesson 2.5](lessons/module-02/lesson-05.md))
- **Escape phase** — A later checkpoint or gate that could have caught a defect and did not ([lesson 5.4](lessons/module-05/lesson-04.md))
- **Escape probability** — The chance a defect passes a series of gates, $\prod_i (1 - c_i)$ for independent catch rates $c_i$ ([lesson 5.4](lessons/module-05/lesson-04.md))
- **Escaped defect** — A bug traced to a ticket after it was deployed, within a fixed window (30 days in this course) ([lesson 13.1](lessons/module-13/lesson-01.md))
- **Evaluation (agent eval)** — A repeatable measurement of how often an agent system (AI layer + agent harness + model) completes a fixed set of tasks, used to decide whether a change helped ([lesson 7.1](lessons/module-07/lesson-01.md))
- **Evaluation harness** — The infrastructure that runs tasks, records trials, grades them and aggregates results; distinct from the agent harness being evaluated ([lesson 7.1](lessons/module-07/lesson-01.md))
- **Evidence ladder** — Ranking of interview answers from compliments and future promises up to specific past events, workarounds and commitments ([lesson 1.4](lessons/module-01/lesson-04.md))
- **Evolution policy (method)** — One page saying what triggers a review of the method, who decides and how teaching materials follow; distinct from the AI-layer governance policy ([lesson 14.3](lessons/module-14/lesson-03.md))

## Q

## R

## T
