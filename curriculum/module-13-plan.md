# Module 13 plan — Measuring AI Engineering Impact

6 lessons · ~100 min instruction · ~6 h practice + 3–6 weeks of data · depends on Module 5 (`NOTES.md`, the 6-ticket paste-and-go vs loop comparison), Module 7 (Wilson intervals, task clustering, paired designs, A/A runs, pinned versions) and, lightly, Modules 10–11 (cost per task, run ledgers) and Module 12 (gateway logs as a cost data source).

Module 7 measured the agent system on a fixed task set. Module 13 measures the **engineering organization**: tickets, PRs, defects and hours of real people doing real work, where the student does not control the task mix and cannot rerun a ticket. The statistics extend from binomial rates to skewed continuous metrics (log scale, bootstrap, permutation, effect sizes) and from "is the harness drifting?" to "is this a causal effect?".

Shared lab material: `labs/module-13/` — `tools/ImpactStats` (dependency-free C#: describe, balance, compare, did, assign, power, import-gh), three **illustrative** data sets from a deterministic generator (`data/generate_data.py`): `contoso-selfselected.csv` (no true effect; developers chose AI for small tickets → naive 42% faster, stratified +2%), `contoso-randomized.csv` (true 15% reduction, randomized within developer × size, one 170-hour outlier, contamination, agent version change, higher escaped-defect rate), `prepost-teams.csv` (pilot team picked for its worst quarter → regression to the mean), three fictional claims to critique, a flawed draft report and a worked example report.
