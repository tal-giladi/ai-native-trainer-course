- **Context engineering** — Curating the smallest set of tokens — system instructions, tools, rules, retrieved data and history — that lets an agent do the task, on every turn (lessons/module-04/lesson-01.md)
- **Context window** — The maximum number of tokens (input plus output) a model can attend to in one request; everything in the request counts toward it (lessons/module-04/lesson-01.md)
- **Context budget** — What is left of the window for the task's working material: B = W − S − R − T − H − O (window minus system prompt, rules, tools, history and output reserve) (lessons/module-04/lesson-01.md)
- **Effective context** — The part of the nominal window a model uses reliably for a given task; smaller than the window because recall degrades with length, position and distractors (lessons/module-04/lesson-01.md)
- **Context rot** — Degradation of a model's recall and accuracy as the number of tokens in its context grows (lessons/module-04/lesson-01.md)
- **Prompt caching** — Reusing an identical request prefix across calls at a reduced input price; changes what cached tokens cost, not whether they occupy the window (lessons/module-04/lesson-01.md)
- **Always-loaded context** — Instructions loaded into every session at start, such as a root CLAUDE.md, its imports and rules without a path scope (lessons/module-04/lesson-02.md)
- **On-demand context** — Instructions that load only when a trigger fires, such as a path-scoped rule when a matching file is read or a skill when invoked (lessons/module-04/lesson-02.md)
- **Progressive disclosure** — Letting the agent discover context step by step from lightweight identifiers (paths, queries, links) instead of loading everything up front (lessons/module-04/lesson-02.md)
- **Just-in-time retrieval** — Loading data into context with tools at the step that needs it, rather than pre-loading it (lessons/module-04/lesson-02.md)
- **Topology map** — A short, annotated file tree with a "where does X go?" table, referenced by path and regenerated from the repository when folders move (lessons/module-04/lesson-02.md)
- **Decision before trigger** — The layering rule that a fact the agent must act on before it would open a file under the trigger path belongs, or has a pointer, in the always-loaded layer (lessons/module-04/lesson-02.md)
- **Context pollution** — Residue in a session's history — failed attempts, abandoned plans, large tool outputs — that degrades later turns and disappears with a reset (lessons/module-04/lesson-03.md)
- **Contradictory context** — Two loaded instructions that disagree, within a file, across files, across directory levels or across tools; typically produces answers that flip between runs (lessons/module-04/lesson-03.md)
- **Redundant context** — The same fact stated more than once, or stated when the code already makes it clear; costs tokens and drifts into contradiction (lessons/module-04/lesson-03.md)
- **Irrelevant context** — True information that does not apply to the repository or task, acting as a distractor (lessons/module-04/lesson-03.md)
- **Compaction** — Replacing older conversation history with a model-written summary so a session can continue; lossy by design (lessons/module-04/lesson-04.md)
- **Compact instructions** — Guidance in the root CLAUDE.md, or a focus passed to /compact, that tells the summarizer what must survive (lessons/module-04/lesson-04.md)
- **Handoff note** — A short task file (goal, verbatim constraints, decisions, done, next, open questions) that lets a fresh session continue after /clear or compaction (lessons/module-04/lesson-04.md)
- **Context audit** — Sorting every piece of a context layer into must always know, retrieve when needed, never load or generate dynamically, then proving the change on a fixed task set (lessons/module-04/lesson-05.md)
- **Task set** — A fixed list of tasks with deterministic grading, run before and after a change in fresh sessions to detect regressions (lessons/module-04/lesson-05.md)
- **Ablation** — Removing or restoring one element at a time and rerunning the affected tasks to find which element a result depends on (lessons/module-04/lesson-05.md)
- **Cost per passing answer** — Total cost of a set of runs divided by the number of runs that passed; the cost of one useful result (lessons/module-04/lesson-05.md)
