- **token** — The unit a language model reads and writes: a sub-word piece from a fixed vocabulary; pricing, rate limits and context windows are all counted in tokens (lessons/module-02/lesson-01.md)
- **tokenizer** — The algorithm and vocabulary that split text into tokens; differs between vendors and model generations, so the same text has different counts (lessons/module-02/lesson-01.md)
- **byte-pair encoding (BPE)** — Tokenization method that builds a vocabulary by repeatedly merging the most frequent adjacent byte pairs; frequent strings become one token, rare ones fragment (lessons/module-02/lesson-01.md)
- **embedding** — The vector a token ID is mapped to before the transformer layers process it (lessons/module-02/lesson-01.md)
- **attention** — The mechanism by which each token weighs earlier tokens through a softmax over query-key scores; the weights compete, so irrelevant context can dilute relevant context (lessons/module-02/lesson-01.md)
- **logits** — The raw, unnormalised scores a model outputs for every vocabulary entry as the next token (lessons/module-02/lesson-01.md)
- **context window** — The maximum number of tokens, input plus output, a model can attend over in one request (lessons/module-02/lesson-01.md)
- **effective context** — The length of context over which a model still performs a given task reliably; usually much smaller than the advertised window (lessons/module-02/lesson-01.md)
- **KV cache** — Stored keys and values of earlier tokens that let a model generate each new token without recomputing the whole prefix (lessons/module-02/lesson-01.md)
- **needle-in-context test** — A probe that hides a fact at chosen positions in a long context and checks whether the model retrieves it; the multi-needle variant adds conflicting distractors (lessons/module-02/lesson-01.md)
- **softmax** — The function that turns logits into probabilities summing to 1: $p_i = e^{z_i/T} / \sum_j e^{z_j/T}$ (lessons/module-02/lesson-02.md)
- **temperature** — A decoding parameter that divides logits before softmax; low values sharpen the distribution, high values flatten it; not available on every current model (lessons/module-02/lesson-02.md)
- **top-p (nucleus) sampling** — Sampling only from the smallest set of most-likely tokens whose cumulative probability reaches p, after renormalising (lessons/module-02/lesson-02.md)
- **greedy decoding** — Always choosing the highest-probability token; the limit of temperature approaching 0; repeatable but not necessarily correct (lessons/module-02/lesson-02.md)
- **reasoning (thinking) tokens** — Intermediate tokens a reasoning model generates before its answer; billed as output tokens even when hidden (lessons/module-02/lesson-02.md)
- **instruction hierarchy** — The trained tendency of a model to prioritise instructions by channel (system, developer, user) over text arriving as data; a tendency, not an enforcement mechanism (lessons/module-02/lesson-03.md)
- **chain of command** — OpenAI Model Spec term for the ordered levels of instruction authority; tool outputs and file contents carry no authority unless delegated (lessons/module-02/lesson-03.md)
- **persuasion vs enforcement** — Instructions change the probability of an action; hooks, permissions and CI gates change whether it is possible (lessons/module-02/lesson-03.md)
- **tool calling** — A model emitting a structured request (tool name plus JSON arguments) for a function that the harness, not the model, executes (lessons/module-02/lesson-04.md)
- **agent loop** — The harness cycle of calling the model, executing requested tools, returning results and repeating until the model stops or a limit is hit (lessons/module-02/lesson-04.md)
- **harness** — The code around a model that holds conversation state, executes tools, enforces permissions and bounds the loop (lessons/module-02/lesson-04.md)
- **strict tool use** — A provider option that constrains tool arguments to match the JSON Schema exactly; guarantees shape, not safety or correctness (lessons/module-02/lesson-04.md)
- **workflow (vs agent)** — An LLM system whose steps follow a predefined code path, as opposed to an agent that decides its own next step (lessons/module-02/lesson-04.md)
- **failure taxonomy** — The ten-class scheme for agent failures (hallucination, incorrect or incomplete reasoning, stale, insufficient or conflicting context, tool, instruction, planning, verification) (lessons/module-02/lesson-05.md)
- **escape cause** — The reason a failure was not caught before it reached review or production, recorded alongside its primary cause (lessons/module-02/lesson-05.md)
- **cost per successful task** — Cost per attempt divided by success probability, plus expected failures times the human cost of handling one failure (lessons/module-02/lesson-05.md)
- **hard constraint (model selection)** — A requirement such as residency or data-use terms that eliminates a model before any scoring, rather than being weighted (lessons/module-02/lesson-05.md)
