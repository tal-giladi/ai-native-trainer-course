- **MCP host** — The application the user works in (Claude Code, Cursor, VS Code with Copilot) that runs the model and holds one MCP client per connected server (lessons/module-08/lesson-01.md)
- **MCP client** — The connector inside a host that maintains the connection to exactly one MCP server (lessons/module-08/lesson-01.md)
- **MCP server** — A program, local (stdio) or remote (Streamable HTTP), that exposes tools, resources or prompts to MCP clients (lessons/module-08/lesson-01.md)
- **MCP tool** — A model-controlled function exposed by an MCP server, described by a name, a description and a JSON Schema for its inputs (lessons/module-08/lesson-01.md)
- **Tool annotation** — Optional hints on an MCP tool such as `readOnlyHint` or `destructiveHint`; clients must treat them as untrusted unless the server is trusted (lessons/module-08/lesson-01.md)
- **stdio transport** — MCP transport in which the host starts the server as a subprocess and exchanges newline-delimited JSON-RPC over stdin and stdout; stdout is reserved for protocol messages (lessons/module-08/lesson-01.md)
- **Streamable HTTP** — MCP transport for remote servers in which each message is an HTTP POST to one endpoint; authorization uses OAuth 2.1 (lessons/module-08/lesson-01.md)
- **Token passthrough** — The anti-pattern, forbidden by the MCP specification, of a server accepting a token not issued for it and forwarding it to a downstream API (lessons/module-08/lesson-01.md)
- **Permission layers** — The three independent controls on what an agent can do through an integration: credential scope, server tool surface and host rules; effective power is their intersection (lessons/module-08/lesson-01.md)
- **Fine-grained personal access token** — A GitHub token restricted to selected repositories and specific permissions such as Issues read-only; recommended by GitHub over classic tokens (lessons/module-08/lesson-02.md)
- **Read-only mode** — A server-side switch (for example the GitHub MCP server's `X-MCP-Readonly` header) that stops a server from offering write tools at all (lessons/module-08/lesson-02.md)
- **Blast radius** — The set of things a misfiring agent could change; estimated in this course as reachable write pairs, write tools times repositories or projects reached (lessons/module-08/lesson-02.md)
- **Provenance** — Where a tool's answer came from and when: source, version, capture time and the reference it was checked against (lessons/module-08/lesson-03.md)
- **Freshness check** — Comparing a data source's version and age with a reference (such as the repository's migration head) and refusing or flagging stale answers (lessons/module-08/lesson-03.md)
- **Tool execution error** — An MCP tool result with `isError: true` that the model can read and act on, as opposed to a protocol error for a malformed request (lessons/module-08/lesson-03.md)
- **Hook** — A command the agent host runs at a lifecycle event (before or after a tool call, at session start, at stop) that can block, validate or record what the agent does (lessons/module-08/lesson-04.md)
- **Fail closed** — A control that denies the action when it cannot evaluate it; required for enforcement hooks, because in Claude Code a hook error other than exit 2 lets the call proceed (lessons/module-08/lesson-04.md)
- **Fail open** — A control that lets the action proceed when it fails; acceptable for audit hooks, which must not block work, and dangerous for enforcement hooks (lessons/module-08/lesson-04.md)
- **Audit hook** — A hook that records each tool call (tool, target, outcome, input hash) with secrets redacted; local logs are evidence for the developer, not a tamper-proof audit trail (lessons/module-08/lesson-04.md)
