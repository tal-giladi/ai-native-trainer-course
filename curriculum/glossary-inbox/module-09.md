- **trust boundary** — The line around content and instructions authored by the user; everything the agent reads from elsewhere (tickets, docs, tool output, dependencies) is untrusted, regardless of who owns the system it came from (lessons/module-09/lesson-01.md)
- **lethal trifecta** — The dangerous combination of access to private data, exposure to untrusted content, and an outbound channel in one agent session; all three present means an injection can exfiltrate (lessons/module-09/lesson-01.md)
- **Agents Rule of Two** — Meta's design rule that an agent session should satisfy at most two of {untrusted input, sensitive access, external communication}, assuming injection will sometimes succeed (lessons/module-09/lesson-01.md)
- **indirect prompt injection** — An attack that plants instructions in content the agent later reads, so an innocent user request is hijacked by attacker text the user never typed (lessons/module-09/lesson-02.md)
- **direct prompt injection** — An attack where the user's own input carries an instruction intended to override the system or developer prompt (lessons/module-09/lesson-02.md)
- **sink** — An observable, consequential action an injection aims to reach: a file write, a network POST, a posted comment, a package add, or a settings change (lessons/module-09/lesson-02.md)
- **canary** — A harmless marker value (e.g. CANARY-7f3a) planted so a test can observe whether an attack reached a sink, without any real secret or payload (lessons/module-09/lesson-02.md)
- **tool poisoning** — Hidden instructions embedded in an MCP tool's description, visible to the model but not the user, that steer the agent before or when the tool is used (lessons/module-09/lesson-03.md)
- **rug pull (MCP)** — A server changing its tool descriptions after the user approved it, so a one-time trust decision no longer holds (lessons/module-09/lesson-03.md)
- **package hallucination** — A code-generating model naming a dependency that does not exist; an attacker can register the invented name to deliver malicious code (slopsquatting) (lessons/module-09/lesson-03.md)
- **excessive agency** — Harm arising when an agent can take more consequential actions than the task needs, via excessive functionality, excessive permissions, or excessive autonomy (lessons/module-09/lesson-04.md)
- **exfiltration channel** — A path by which data can leave: network egress, a write/comment tool, files the user will share, or logs and error messages (lessons/module-09/lesson-04.md)
- **approval gate** — A human-in-the-loop checkpoint on a high-impact action, bounding the blast radius of a successful injection to a prompt that can be refused (lessons/module-09/lesson-04.md)
- **fail closed** — A control that denies the action when it cannot function (missing dependency, unreadable input), rather than allowing it; the opposite of fail open (lessons/module-09/lesson-05.md)
- **egress allowlist** — An OS-enforced list of domains a sandboxed command may reach; an empty list means no host is reachable, unlike a command-text deny rule (lessons/module-09/lesson-05.md)
- **residual risk** — The risk that remains after controls are applied, reported as a rate with an interval and accepted by a named owner, never as "safe" (lessons/module-09/lesson-06.md)
- **rule of three** — The approximation that zero events in n trials gives a 95% upper bound on the true rate of about 3/n; used to report residual risk honestly (lessons/module-09/lesson-06.md)
