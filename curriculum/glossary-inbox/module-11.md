- **headless agent** — An agent run with no human in the loop (e.g. `claude -p` in CI), whose context, tools, caps and output format must be set explicitly because nobody can answer a prompt (lessons/module-11/lesson-01.md)
- **run contract** — The written signature of one headless run: what it loads, which tools it may use, its turn and budget caps, and the output it returns (lessons/module-11/lesson-01.md)
- **bare mode** — Claude Code's `--bare` flag: a headless run loads no hooks, skills, MCP servers or CLAUDE.md implicitly, so the job passes the layer and settings it means to use (lessons/module-11/lesson-01.md)
- **permission denial** — A tool call refused in a non-interactive run (e.g. under `dontAsk`); a run can end with subtype `success` while the calls its task needed were denied (lessons/module-11/lesson-01.md)
- **pwn request** — A GitHub Actions vulnerability where a `pull_request_target` workflow checks out and runs untrusted PR code in a job that holds secrets and a write token (lessons/module-11/lesson-01.md)
- **effective false positive** — A review or analysis finding on which developers take no positive action, whether or not it is technically correct; Google keeps checks under 10% (lessons/module-11/lesson-02.md)
- **base-rate ceiling** — The upper bound on a reviewer's precision set by comment volume: precision ≤ known defects / comments, however good the model (lessons/module-11/lesson-02.md)
- **adjudication** — A human re-examining agent findings that matched no known defect and adding confirmed ones to the ground truth (lessons/module-11/lesson-02.md)
- **acted-on rate** — The share of posted agent comments that lead to a code change; the production signal for CI-review precision (lessons/module-11/lesson-02.md)
- **break-even acceptance** — For a recurring automation, the acceptance rate a* = r/s (review minutes per proposal over minutes saved per accepted proposal) below which it costs more time than it saves (lessons/module-11/lesson-03.md)
- **propose, validate, apply** — Automation pattern where the agent only returns structured proposals, a deterministic validator checks them against a policy, and a separate step holding the only write token applies them (lessons/module-11/lesson-03.md)
- **idempotency key** — A value (e.g. issue id plus proposal hash, or the ISO week) that lets a repeated or late run detect work already done and exit without spending (lessons/module-11/lesson-03.md)
- **kill switch** — A single setting (e.g. repository variable `AGENTS_ENABLED`) that stops every agent job without a code change (lessons/module-11/lesson-04.md)
- **shadow run** — Running a candidate prompt, model or agent version on the same inputs as production with its output kept unpublished, to compare both on the same outcomes (lessons/module-11/lesson-04.md)
- **run ledger** — One record per agent run (job, subtype, turns, cost, duration, outcome, attempt) from which cost per useful outcome, retries and ceiling breaches are computed (lessons/module-11/lesson-04.md)
- **cost per useful outcome** — Total cost of an agent job divided by the number of its outputs that were applied or merged (lessons/module-11/lesson-04.md)
- **budget breaker** — A scheduled check that sums the day's agent spend and disables the offending workflows when a ceiling or a retried cap failure is found (lessons/module-11/lesson-04.md)
- **change class** — A category of AI-layer change (wording, behavior, capability and trust, platform) that sets the review and evidence it needs (lessons/module-11/lesson-05.md)
- **system-evolution policy** — The team's loop for agent mistakes: incident note, regression task that fails, smallest fix, gate, changelog entry, periodic review (lessons/module-11/lesson-05.md)
- **enforcement ladder** — The ordering of ways to encode a rule, from least to most reliable: a sentence in the rules, a skill step, a hook or gate, a test in the build (lessons/module-11/lesson-05.md)
