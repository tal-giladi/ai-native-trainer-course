- **Skill** — A versioned procedure file (in the Agent Skills format, `SKILL.md` plus optional scripts and references) that an agent loads on demand, either when its description matches the request or when a user invokes it by name (lessons/module-06/lesson-01.md)
- **Skill trigger** — What makes a skill load: its description (model invocation), its `/name` (user invocation) and optional path scopes; measured by trigger recall and false-trigger rate (lessons/module-06/lesson-01.md)
- **Output contract** — The observable result a skill or agent promises (artifacts, paths, sections, invariants), written so a script can check most of it (lessons/module-06/lesson-01.md)
- **Deterministic step** — A step of a skill with exactly one right answer, done by a script or command rather than by the model (lessons/module-06/lesson-01.md)
- **Progressive disclosure** — Loading a skill in levels: metadata always, the body when activated, reference files and script output only when a step needs them (lessons/module-06/lesson-01.md)
- **Core skills** — The five procedure skills that cover the course's loop: prime, spec, plan-feature, validate and pr-review (lessons/module-06/lesson-02.md)
- **Handoff through files** — Chaining skills by having each write an artifact on disk that the next one reads and checks, so the chain survives resets, compaction and a change of person or tool (lessons/module-06/lesson-02.md)
- **Prompt chaining** — A fixed sequence of model steps with programmatic checks between them; a workflow rather than an agent choosing its own path (lessons/module-06/lesson-02.md)
- **Sub-agent** — A delegated agent run with its own context window, system prompt, tools and model, which returns one message to its caller and cannot ask the user questions mid-task (lessons/module-06/lesson-03.md)
- **Context isolation** — Keeping a delegated task's reading and tool output out of the caller's context, so only its summary returns (lessons/module-06/lesson-03.md)
- **Delegation contract** — What a delegation must carry: objective, output format, tools and sources, boundaries, and what to do with unknowns (lessons/module-06/lesson-03.md)
- **Trigger recall** — The share of should-load requests on which a skill actually loaded, over repeated runs (lessons/module-06/lesson-04.md)
- **False-trigger rate** — The share of should-not-load (near-miss) requests on which a skill loaded anyway (lessons/module-06/lesson-04.md)
- **Golden check** — A per-ticket rule file listing facts a correct skill output must contain; a regression test for a skill (lessons/module-06/lesson-04.md)
- **Cold-use test** — A colleague uses a skill on a ticket of their choosing without any help; where they get stuck shows the skill's unclear inputs and outputs (lessons/module-06/lesson-04.md)
