- **AI layer** — The versioned set of files in a repository that shape coding-agent behavior: rules files, skills, sub-agent definitions, MCP configuration, hooks, CI agent workflows, eval tests and their governance (lessons/module-03/lesson-01.md)
- **Fourth citizen** — The course's name for AI behavior as a first-class repository artifact alongside source, tests and documentation, with versioning, review, testing, ownership and change management (lessons/module-03/lesson-01.md)
- **CODEOWNERS** — GitHub file mapping path patterns to owners who are requested for review; the last matching pattern wins, and review is binding only with branch protection or rulesets (lessons/module-03/lesson-01.md)
- **AI-layer changelog** — A log with one entry per AI-layer change recording what changed, the triggering incident, the evidence and how it was verified (lessons/module-03/lesson-01.md)
- **AGENTS.md** — Open Markdown convention for repository instructions read by many coding agents; the nearest file in the directory tree takes precedence (lessons/module-03/lesson-02.md)
- **Rules file** — An always-loaded instruction file for a coding agent, such as AGENTS.md, CLAUDE.md or copilot-instructions.md (lessons/module-03/lesson-02.md)
- **Path-scoped rule** — An instruction file that loads only when the agent works on files matching a glob (Claude Code `paths`, Cursor `globs`, Copilot `applyTo`) (lessons/module-03/lesson-02.md)
- **Hook** — A script the agent harness runs at a lifecycle event, such as before a tool call, that can deterministically allow or block an action (lessons/module-03/lesson-02.md)
- **Advisory vs deterministic control** — Advisory controls (rules, skills) are context the model weighs; deterministic controls (hooks, permissions, tests, CI gates) run the same way every time (lessons/module-03/lesson-02.md)
- **Portability matrix** — A table showing where each AI-layer rule or component lives in each agent tool and how drift between copies is prevented (lessons/module-03/lesson-02.md)
- **Brownfield audit** — A five-pass review of an existing codebase (topology, build/test, SQL conventions, legacy patterns, tribal knowledge) to find what an agent would get wrong, with evidence (lessons/module-03/lesson-03.md)
- **Evidence ladder** — Ranking of audit sources from executable checks and recent code down to docs, wikis and memory; used to resolve conflicts between sources (lessons/module-03/lesson-03.md)
- **Tribal knowledge** — Conventions a team follows that are written nowhere in the repository and can only be learned from people (lessons/module-03/lesson-03.md)
- **Inference filter** — The test of whether a fresh agent without rules gets a finding wrong in any of k runs; only findings it gets wrong become rules (lessons/module-03/lesson-03.md)
- **Grounded rule** — A rules-file line with a directive, a scope and evidence in the repository that can be re-checked automatically (lessons/module-03/lesson-04.md)
- **Probe** — A short prompt run in several fresh agent sessions with must-mention and must-not-mention checks, used as a smoke test for a rules file (lessons/module-03/lesson-04.md)
- **Convention test** — A unit test that fails the build when code breaks a house convention, guarding both the code and the rules that describe it (lessons/module-03/lesson-04.md)
- **Stale context** — Context that was once true but no longer matches the system, such as a rule describing an abandoned pattern; agents often follow it faithfully (lessons/module-03/lesson-04.md)
