### C-20261010-01 · GuardFall: Adversa AI shows command-text denylists are architecturally bypassable in 10 of 11 popular open-source coding agents (shell rewrite happens after the filter, not before)

- **Class:** A
- **Kind:** new-topic
- **Date discovered:** 2026-10-10
- **Date published:** 2026-06-30 (Adversa AI's report); wide pickup 2026-07-01 to 2026-07-26
- **Source:** Adversa AI's own report could not be located/fetched directly this session (no stable URL surfaced; aviatrix.ai and threatcluster.io mirrors are both blocked by this session's egress proxy). Corroborated via three independent secondary outlets that converge on the same technical detail: https://thehackernews.com/2026/06/guardfall-exposes-open-source-ai-coding.html, https://securityaffairs.com/194546/ai/guardfall-flaw-hits-10-of-11-popular-open-source-ai-agents.html, https://labs.cloudsecurityalliance.org/research/csa-research-note-guardfall-ai-agent-shell-injection-2026070/ (CSA note could not be fetched directly — same proxy block — summarized via search snippet only)
- **Organization/researchers:** Adversa AI
- **Category:** agent-security
- **What changed:** Adversa AI tested 11 popular open-source coding/computer-use agents (Hermes, opencode, Goose, Cline, Roo-Code, Aider, Plandex, Open Interpreter, OpenHands, SWE-agent — combined ~548,000 GitHub stars — plus Continue, the one tool built to resist this class) and found 10 of 11 could be bypassed. Root cause: each tool's permission/safety filter inspects the **raw command string the model produced**, but the shell rewrites that string (quote removal, variable/glob expansion, word-splitting) before executing it — so the filter and the shell are looking at two different representations of the same command. Adversa's seed example: NousResearch's Hermes used a regex denylist that blocked `rm` but not an empty-quoted form like `r''m`; Bash strips the empty quotes and runs `rm` anyway. The Cloud Security Alliance note frames this as architectural, not a per-tool bug: patching one vendor's denylist does not fix the underlying class, because any string-matching filter that runs *before* shell rewriting is bypassable this way.
- **Technical summary:** This is the identical failure mode the course's own lesson 09.5 already names and warns against — "a Bash rule matches the command text as written... isn't a security boundary around the program... For enforcement that does not depend on the command text you need the sandbox" (citing Claude Code's own permissions docs, which make the same admission about Claude Code's `deny: ["Bash(curl*)"]`-style rules). GuardFall is real-world, multi-vendor (10 different tools, not Claude Code), reproducible, concrete evidence for exactly that claim, with a specific worked exploit (empty-quote expansion) the course's lesson currently only argues for in the abstract (`/usr/bin/curl`, `sh -c`, Python socket examples).
- **Why it might matter:** Lesson 09.5's whole argument — "the sandbox is the boundary," not command-text matching — currently rests on reasoning from the Claude Code docs' own admission plus hypothetical bypass examples. GuardFall gives a dated, independently-reported, cross-vendor real-world confirmation of the exact mechanism (shell rewrite happens after the filter sees the string), with a concrete exploit shape (empty-quote/shell-expansion bypass) that could replace or supplement the lesson's existing hypothetical examples and strengthen the Limitations section's "a determined adaptive attacker may still find a path" line with a named, sourced case.
- **Evidence of adoption:** n/a (vulnerability research, not a product feature)
- **Major organizations using it:** n/a — note, none of the affected tools (Hermes, opencode, Goose, Cline, Roo-Code, Aider, Plandex, Open Interpreter, OpenHands, SWE-agent) is the specific product (Claude Code) lesson 09.5 quotes; the course's own named tool is not shown vulnerable by this report, only architecturally analogous tools are.
- **Open-source implementation:** the affected tools themselves are open source (repos named above); no PoC code published by Adversa in what I could reach
- **Paper:** none (industry security report, not an academic paper)
- **Code:** none reachable this session

Not a FIX — nothing currently taught is contradicted; this only strengthens the existing claim with named evidence.
- **Confidence:** medium-high — the core technical claim (filter sees pre-shell-rewrite text) is consistent across three independent outlets (The Hacker News, Security Affairs, a Cloud Security Alliance research note), but I could not reach Adversa AI's own original report or either of the two blocked mirror pages directly, so this is secondary-sourced, not primary-verified, and the exact list of which 10 of 11 tools failed (vs. the one, Continue, that resisted) should be double-checked against Adversa's own page before citing specific tool names in a lesson.
