# Offer ladder — Ground before you generate

> **Illustrative.** One student's ladder, built on the Module 14 reference method (Ground-Bound-Build-Prove), the Module 17 workshop and the Module 13 experiment EXP-01. Prices are placeholders of a plausible size for a US-dollar market as of 2026-09; yours come from your own pricing worksheets. Check with `OfferCheck ladder`.

- Positioning: For engineering leads of legacy .NET and SQL Server teams whose coding-agent PRs keep failing review, unlike generic AI-tool training, I help the team ground the agent in the rules their code already has, and measure on their own tickets whether it helped.
- Wedge: legacy .NET + SQL Server teams on Jira that already use a coding agent weekly
- Capacity: 8 working days a month; at most one pilot or implementation at a time, two workshops a month, two retainers. The application form states this cap.
- Currency: USD, excluding taxes

## Why this order

Each rung produces the evidence the next one needs: the workshop measures learning (level 2), the pilot measures delivery on the client's own tickets, the implementation repeats that measurement across teams, and the retainer keeps the evaluation running when models change. A buyer can stop after any rung with something useful and nothing unfinished.

## What is not on the ladder

- A fixed "productivity improvement" at any price. Outcomes are measured and reported with intervals, never promised.
- Work on production systems, or access to the client's production data.
- Anything for my employer's customers, competitors or suppliers (see the admin register).
