SqlHelper still exists because reporting queries are a different workload from transactional ones: they return wide, dynamic result sets that fit naturally into a DataSet. The ADR moved transactional code to Dapper repositories, but reports were intentionally left on SqlHelper, which is why MonthlyRevenueReport uses it. If you are writing a new report, follow that precedent and use SqlHelper.ExecuteDataSet so all reports stay consistent. For normal CRUD code, use a Dapper repository behind an interface. Keeping these two paths separate makes each simpler.
