# Module 21 labs — Delivering engagements

Everything the Module 21 labs need. Lessons: [21.1](../../lessons/module-21/lesson-01.md) · [21.2](../../lessons/module-21/lesson-02.md) · [21.3](../../lessons/module-21/lesson-03.md) · [21.4](../../lessons/module-21/lesson-04.md) · [21.5](../../lessons/module-21/lesson-05.md).

The lab is a **full dry-run engagement** before a real one. The client is simulated: Contoso Ltd, whose code is your own `brownfield-demo` from [Module 15](../module-15/README.md) at tag `before-ai-layer`. You run the whole cycle — discovery, kickoff, audit, baseline, architecture, build, enable, measure, handover, follow-up, case study — against the dry-run SOW in [`client/sow-contoso.md`](client/sow-contoso.md), with the tools you already have: `AiLayerTool` ([Module 3](../module-03/README.md)) for the audit, `EvalHarness` ([Module 7](../module-07/README.md)) for the eval baseline and gate, `ImpactStats` ([Module 13](../module-13/README.md)) for the delivery baseline and comparison, `AdoptCheck` ([Module 19](../module-19/README.md)) for usage after handover, `OfferCheck` ([Module 20](../module-20/README.md)) for the SOW. `EngageCheck` (this folder) checks the engagement record phase by phase. Then you do it again, for real, with a paid or pilot client.

> [!CAUTION]
> The dry run is fictional; the real engagement is not. In a real engagement you work on **client code and client data**: only on the machines and accounts the SOW allows, never with production access, never pasting client code into tools the client has not approved, and never keeping exports after the SOW's deletion date. Your engagement record names people: keep it in a private repository. Nothing about a client — not even the anonymized case study — is published without the client's written approval of the exact text. If the client is your employer's customer, or you use employer material, you need your employer's written permission first ([20.5](../../lessons/module-20/lesson-05.md)).

## Requirements

- .NET SDK 8 or newer (`RollForward=Major`). Verified with SDK 10.0.400.
- No NuGet packages. `EngageCheck` is read-only and deterministic; it works offline.
- `brownfield-demo` assembled from Module 15 (`bash ../module-15/scripts/assemble-demo.sh --out ../../../brownfield-demo`), with a `before-ai-layer` worktree.
- The Module 3, 7, 13, 19 and 20 tools (built on first `dotnet run`).
- For the interviews: a peer to play the stakeholders from [`client/brief.md`](client/brief.md), or an agent you instruct to stay in character using only those notes.
- Python 3 only to regenerate the illustrative data (`py scripts/generate_data.py`).

## Quick start

From this folder:

```bash
E="dotnet run --project tools/EngageCheck --"

# 21.1 — discovery, kickoff and stakeholder mapping
$E kickoff break/21.1-thin-kickoff/engagement-record.md                 # 16 errors, 4 warnings
$E kickoff solution/engagement-record.md                                # clean

# 21.2 — technical audit and baseline
dotnet run --project ../module-03/tools/AiLayerTool -- scan ../../../demo-before
dotnet run --project ../module-13/tools/ImpactStats -- describe client/data/baseline-tickets.csv --metric cycle_hours --by size
dotnet run --project ../module-13/tools/ImpactStats -- power --sd 0.44 --effect 0.38     # 14 tickets per arm
$E baseline break/21.2-late-baseline/engagement-record.md               # 11 errors, 10 warnings
$E baseline solution/engagement-record.md                               # clean

# 21.3 — architecture and build with the team
$E build break/21.3-built-for-them/engagement-record.md --log break/21.3-built-for-them/prs.csv   # 12 errors; truck factor 0
$E build solution/engagement-record.md --log solution/prs.csv          # clean; truck factor 2

# 21.4 — enable, measure, hand over, follow up
dotnet run --project ../module-13/tools/ImpactStats -- compare client/data/pilot-tickets.csv --metric cycle_hours --a manual --b ai --strata size
dotnet run --project ../module-07/tools/EvalHarness -- compare client/data/eval-results.csv --a before-ai-layer --b contoso-layer-v1
dotnet run --project ../module-19/tools/AdoptCheck -- usage client/data/usage.csv --events client/data/events.csv
dotnet run --project ../module-19/tools/AdoptCheck -- usage break/21.4-calendar-handover/usage.csv --events break/21.4-calendar-handover/events.csv
$E handover break/21.4-calendar-handover/engagement-record.md           # 12 errors, 5 warnings
$E handover solution/engagement-record.md                               # clean

# 21.5 — the anonymized case study
$E casestudy break/21.5-leaky-case-study/case-study.md --record solution/engagement-record.md --deny solution/deny-terms.example.txt   # 17 errors
$E casestudy solution/case-study.md --record solution/engagement-record.md --deny solution/deny-terms.example.txt                     # clean
```

(PowerShell: type the full `dotnet run --project tools/EngageCheck -- <command>` instead of `$E`.) Exit code 0 means clean, 1 means errors, 2 means a usage problem. `EngageCheck` checks structure, wording and arithmetic; it cannot tell whether a stakeholder told you the truth or whether a client will approve your text.

## File formats

- **Engagement record**: markdown with `- Key: value` fact lines and tables found by their column names; see the [engagement playbook template](../../templates/engagement-playbook.md). Add columns and rows freely; keep the header names.
- **prs.csv**: `pr,week,author,author_side,reviewer,reviewer_side,area,mode,files` — sides `client`, `consultant` or `none`; area `ai-layer`, `code`, `ci` or `docs`; mode `solo`, `pair` or `mob`; files separated by `;`. The consultant's handle must match the `Consultant:` line, e.g. `Student (S)`.
- **Case study**: markdown per the [case-study template](../../templates/case-study.md), with a `- Client approval:` line.
- **Deny list**: one term per line, `#` for comments. Keep your real list outside every repository you publish.

## The dry run, week by week

| Engagement week | You do | Check |
|---|---|---|
| before 1 | Interview the nine stakeholders (20 minutes each, role-played); request the security review | — |
| 1 | Kickoff; working agreement; premortem; record section 1 | `EngageCheck kickoff` |
| 1–2 | Audit `before-ai-layer`; baseline from `client/data`; eval baseline; pre-registration (D1, D2) | `AiLayerTool scan`, `ImpactStats describe`/`power`, `EngageCheck baseline` |
| 3–6 | Rebuild the AI layer on a branch of `before-ai-layer` **with** the team: the role-played developers author, you pair; keep `prs.csv` | `EngageCheck build` |
| 6–10 | Run your Module 17 workshop for the other two teams (a peer group); hand office hours to their owner | `AdoptCheck usage` |
| 11 | Results with intervals; read-out; "what this does not show" (D5) | `ImpactStats compare`, `EvalHarness compare`, `EngageCheck handover` |
| 12, +30/60/90 days | Handover; follow-ups on the usage data | `AdoptCheck usage`, `EngageCheck handover` |
| after | Case study, "approved" by the peer who played the sponsor | `EngageCheck casestudy` |

## Expected results

| Check | Break | Reference |
|---|---|---|
| `kickoff` (21.1) | 16 errors: no security or business stakeholder, promises in success criteria ("at least 30% faster", "10x", "guaranteed"), a high-influence person without a plan, acceptors "S", "client", "the team", undated access, no data handling, a one-line premortem without an owner | 0 |
| `baseline` (21.2) | 11 errors: four findings "confirmed" from a 2021 doc, memory or one source; baseline captured 2026-10-30 (build started 10-19), per-developer, two weeks, no spread, no guardrail | 0 |
| `build` (21.3) | 12 errors: 0% client-authored AI-layer changes in every third, five consultant changes merged unreviewed, no client author, client truck factor 0 over 29 files, four decisions taken by the consultant | 0; 33% → 83% → 83% client-authored, truck factor 2 |
| `handover` (21.4) | 12 errors: office hours and metrics owned by the consultant, nothing run without the consultant, no eval-gate owner, a pooled-median −23% with no interval called "improved", defects "improved" on an interval touching zero, no follow-ups, no "does not show" | 0 |
| `AdoptCheck usage` (21.4) | 4 errors: every team below its limit from W19 (decay), 21% active in W24 | 0; platform below its limit in W19, recovered after the 60-day follow-up |
| `casestudy` (21.5) | 17 errors: client, sponsor and controller named, an e-mail address, "23%" that is not in the record, "up to 40", claims on two inconclusive outcomes, no approval, no limitations | 0 |
| `OfferCheck sow client/sow-contoso.md` | — | 0 |
